# Контентні сторінки послуг Body Restore

## Ціль

Дати людині й пошуковим системам окремі зрозумілі сторінки для кожної з десяти реально заявлених послуг, не дублюючи технічний iframe-шаблон і не вигадуючи медичні або комерційні дані.

## Контекст

- Публічний сайт — статичний Next.js export для `https://body-re.store`.
- Поточна головна сторінка — existing one-page шаблон; він залишається джерелом візуального стилю.
- Факти про послуги, адресу і попередній запис беруться з `massage_business_info.md`.
- У наданому джерелі немає затверджених цін, тривалостей, графіка, освіти спеціаліста чи медичних діагнозів.

## Що змінюємо

- Додаємо `/services/` та десять статичних URL `/services/[slug]/`.
- Для кожної сторінки генеруємо canonical metadata, `Service` JSON-LD, внутрішні посилання та CTA на дзвінок/контакти.
- Додаємо з головної посилання до каталогу послуг.
- Позначаємо внутрішній `sharp-template` як `noindex,follow`; він лишається тільки iframe-реалізацією головної.
- SEO-артефакти автоматично включають тільки нові канонічні Next.js сторінки.

## Що не змінюємо

- Не створюємо сторінки для непідтверджених послуг, районів Одеси або фіктивних цін.
- Не змінюємо канал production: static export → FTP → live manifest → notification.
- Не додаємо SSR, API або нові залежності.
- Не описуємо масаж як лікування діагнозів і не обіцяємо гарантований результат.

## Ризики

- Сторінки з однаковим текстом були б дублями; кожна використовує власний опис, сценарії звернення й особливу примітку.
- Медичні формулювання можуть бути некоректними; використовуємо обережні слова «може», «після уточнення самопочуття», «не замінює консультацію лікаря».
- Відсутність затверджених цін означає, що вартість і тривалість уточнюються під час попереднього запису.

## План

1. Описати всі підтверджені послуги у типізованому локальному джерелі даних.
2. Додати статичний каталог, динамічний маршрут із `generateStaticParams()` і metadata.
3. Підключити обережну `Service` JSON-LD та канонічні внутрішні посилання.
4. Перевірити сторінки тестом, статичною збіркою та браузером на mobile, tablet і desktop.
5. Задеплоїти тільки перевірений commit та перевірити його на production.

## Перевірка

- `npm run test:seo`
- `npx playwright test tests/e2e/seo-pages.spec.ts`
- `npm run build:static`
- `npx playwright test` з `BODYRES_TEST_URL=https://body-re.store`
- Production smoke для sitemap, `llms.txt`, feed, canonical URL і сторінок послуг.

## Критерії готовності

- Є каталог і 10 окремих URL для всіх підтверджених послуг.
- Кожен URL містить H1, canonical metadata, JSON-LD, доступний CTA та безпечне пояснення.
- `sitemap.xml`, `llms.txt` і feed містять нові URL, але не `/sharp-template/Sharp`.
- На 320, 768, 1366 і 1920 CSS px немає горизонтального скролу, неперекритого тексту чи критичних console errors.
