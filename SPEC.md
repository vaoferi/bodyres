# SPEC.md — BodyRes Sharp Main File one-page

## Ціль
Перевести BodyRes на класичний one-page у стилі `design-7-sharp-main-file.md`, але з реальним контентом BodyRes замість демо-даних. Окремо прибрати QR-постери з основного UI і показати соціальні канали через іконки та текстові лінки.

## Контекст
- Проєкт: Next.js App Router.
- Джерело контенту: `massage_business_info.md`.
- Джерело готових блоків і ритму: `Elements/Sharp Main File/` та інші готові донори з `Elements/`.
- Поточна сторінка була занадто м’якою, пастельною і розтягнутою, тому втрачала відчуття класичного structured landing.
- Користувач прямо попросив не робити QR-коди великими картинками, а ставити іконки соцмереж.

## Що змінюємо
- Оновлюємо головну сторінку до one-page структури в стилі Sharp Main File.
- Окремо підсилюємо головний above-the-fold текст і додаємо hover-описи до сервісних карток, щоб людина бачила користь послуги без зайвого скролу.
- Підтягуємо композицію з готових донорів:
  - hero з виразним serif-headline;
  - щільні секції без пустих полів;
  - темний footer/contact block;
  - social icons замість QR-сурогатів.
- Зберігаємо всі 10 послуг, адресу, телефон, попередній запис, перші ефекти та фінальний CTA.
- Вирівнюємо контакти так, щоб вони виглядали як один акуратний блок, а не набір випадкових карток.
- Окремо переробляємо блок відгуків: беремо реальні відгуки з `Elements/Відгуки`, додаємо 5 зірок, аватари/заглушку для фото та короткі цитати з донорів замість демо-тексту.

## Що не змінюємо
- Джерело правди по контенту.
- Next.js App Router архітектуру.
- Production deploy без окремої команди користувача.

## Ризики
- Якщо перестаратися з темним фоном, сторінка може стати надто важкою.
- Якщо зберегти енерго-motion spacing, Sharp-ритм знову розмиється.
- Якщо в контактному блоці залишити QR-візуали, це суперечитиме прямій вимозі користувача.

## План
1. Оновити design docs і rules під `design-7-sharp-main-file.md`.
2. Перебудувати hero, services, results, gallery і contacts під Sharp-каркас.
3. Перевірити build і візуальний рендер у браузері.
4. Підняти зміни на live URL через NAS/deploy.

## Перевірка
- `npm run build`
- `npm run lint`
- Браузерна перевірка desktop + mobile.
- Перевірка, що на сторінці немає QR-картинок як основного елемента контакту.

## Критерії готовності
- Сторінка має one-page структуру і читається як цілісний класичний лендинг у дусі `design-7-sharp-main-file.md`.
- Соціальні канали показані іконками, а не QR-постерами.
- Інформація з `massage_business_info.md` видима без втрат.
- Візуально немає пустих провалів, блідого вигляду або випадкових карток, що вибиваються з ритму.
