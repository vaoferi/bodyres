---

## 🧠 Фундаментальні Принципи

- Не перенаправляй на користувача виконання задач, які може виконати сам.
- Пояснюй спрощено — як для 12-річного, без складних термінів.
- Шукай глобальну причину проблеми, не ліпи тимчасові "затички".
- Не нашкодь: рішення не повинно руйнувати архітектуру.
- Кодування: UTF-8 без BOM.
- Коментарі — коротко, без слідів ШІ.
- CSS: Mobile First від 320px, `rem`/`clamp()`, без горизонтальних скролів.
- **View Transition API** — для плавних переходів між сторінками.

---

## 📋 Стек та Архітектура

- **Framework:** Next.js 14+ (App Router)
- **Styling:** Tailwind CSS + чистий CSS для кастомних компонентів
- **UI бібліотека:** shadcn/ui (раніше — дизайн-донори з Elements/)
- **Мова:** TypeScript
- **Адаптив:** Mobile First, breakpoints — 640/768/1024/1280/1536px

## 🎯 Цілі розробки

- **Root Cause:** знаходити та виправляти першопричину, а не наслідки.
- **Якість:** не руйнувати існуючий функціонал.
- **Верифікація:** Done = перевірено візуально.
- **Ефективність:** мінімум змін для задачі.

---

## ✅ Definition of Done

- **Фронтенд:** HTTP 200 недостатньо — перевір візуально: верстка, текст, зображення.
- **Помилки:** знайшов баг — виправ до завершення.
- **Фінальне:** перевірка у робочому середовищі.

---

## 🗂️ Design Donors (Elements/)

Це **бібліотека готових компонентів** для копіювання блоків/елементів:
- `/Elements/site/` — RD Navbar, Swiper слайдери, форми
- `/Elements/beautyhouse-html-tm/` — Bootstrap spa-шаблон
- `/Elements/Bliss - HTML5 Template/` — Multipurpose HTML
- `/Elements/Sharp Main File/` — класичний beauty/salon landing page донор з hero, service grid, gallery і footer

**Не використовувати як є.** Копіювати тільки потрібні CSS/HTML-блоки і адаптувати.

Перед тим як вигадувати новий UI-блок, спочатку шукай готовий донор у `/mnt/synology/BodyRes/Elements` і тільки потім вирішуй, чи реально треба щось генерувати з нуля. Для класичної сторінки BodyRes спершу дивись `/Elements/Sharp Main File/`.

Якщо в `Elements/` уже є готова структура для hero, services, testimonials, forms або contacts, бери її як основу і адаптуй під контент BodyRes, а не малюй порожній екран заново.

Якщо донорська картинка містить текст, цифри, список послуг або результати, не ліпи її великим блоком на сайт. Спочатку витягни зміст у нормальний текст і тільки потім вирішуй, чи потрібна сама картинка як візуальна підтримка.

Якщо мова про канали зв'язку, не втискай QR-коди картинками в основний UI. Для BodyRes спочатку став іконки соціальних мереж або текстові лінки, а QR використовуй тільки як допоміжний елемент і лише коли він справді потрібен.

## 🚫 Hard Stops

- Не використовувати localhost:3000 як production proxy.
- Не копіювати дизайн-донори цілком — тільки окремі блоки.
- HTTP 200 не єдиний доказ готовності.
